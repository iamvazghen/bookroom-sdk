## [2.0.0] - 2026-10-06

The release that makes the package usable on a machine that has never seen the
engine.

### Added

- **The engine now ships inside the package.** The 19 engine modules the SDK
  calls are vendored into `bookroom_sdk/_engine` and installed as package data.
  `pip install bookroom-sdk` is the whole setup: no checkout, no `PYTHONPATH`,
  no `BOOKROOM_APP_ROOT`. The 16 webapp, worker and deployment modules are
  excluded, so the package does not drag in Clerk, Prisma, PostgreSQL or S3.
- `_engine/PROVENANCE.md`, documenting the included and excluded module sets and
  how to re-derive them.
- **`verify_clean_install.py`** — builds a throwaway virtual environment,
  installs the package from source, and runs a complete summarization in a
  subprocess with no `BOOKROOM_APP_ROOT`, no `PYTHONPATH` and no engine
  checkout on the path.
- `GET /v1/download` on the facade, which streams a generated artifact. The
  route is confined to the directory holding the named report and rejects any
  name that escapes it.
- React bindings: `useBookroomClient`, `useBookroomJob`, `useBookroomDescribe`,
  `useBookroomHealth`, `BookroomProvider` and a dependency-free
  `<StudyGuidePanel>`, exported from `bookroom-sdk/react`.
- Next.js bindings: `getServerBookroom`, Server Action factories and a
  route-handler adapter, exported from `bookroom-sdk/next`.
- Four runnable example projects: `typescript`, `javascript`, `react`, `nextjs`.
- `SKILL.md`, an integration guide for AI agents.
- `retry_run.py`, which retries a run across transient provider failures and
  resumes from the last checkpoint.
- `tools/time_model.py` and `tools/measure_books.py`, which derive and
  re-measure the time-savings figures published in the README.
- `LICENSE` (MIT), `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`,
  `CITATION.cff`, `CHANGELOG.md` and a CI workflow.

### Changed

- `BOOKROOM_APP_ROOT` is now an **optional override** for developing against a
  live engine checkout. It is no longer required.
- Real runtime dependencies are declared (`pymupdf`, `reportlab`, `Markdown`,
  `beautifulsoup4`, `ebooklib`) instead of "install the application first".
  `ollama` and `tqdm` moved to the `[legacy]` extra, which only the alternate
  Ollama/OpenRouter transport needs.
- `__version__` reads installed package metadata instead of a constant, which
  had already drifted from `pyproject.toml`.
- Errors are a stable hierarchy (`ConfigError`, `UnsupportedSourceError`,
  `ExtractionError`, `BudgetExceededError`, `ValidationError`, `QuotaError`,
  `ProviderError`, `CancelledError`, `JobError`) rather than application
  internals leaking out.
- TypeScript emits ESM and CommonJS with declaration maps, and ships
  `bookroom-sdk/react` and `bookroom-sdk/next` subpath exports.

### Fixed

- `from_env()` ignored `.env` files entirely and reported `not_configured` for
  setups that actually worked.
- The application-root search indexed `parents[4]` unconditionally, raising
  `IndexError` at import in any normal install layout.
- `from_env(app_root=...)` did not use that root to locate the engine's `.env`.
- The discovery error message named the symptom but not the fix.
- `merge_markdown` did not create the destination's parent directory.
- `study_guide` ran generation only, silently producing no PDF, concept map,
  claim audit, manifest or usage report. It now performs the whole job, the
  same sequence the application runs for a real upload.
- The engine's deprecated `fitz` import printed a warning onto stdout, which
  broke `bookroom extract | jq`. The vendored engine prefers `pymupdf`.
- The facade's `review-report` job demanded a `path` it never used.

### Known limitations

- The real-provider end-to-end run has not completed against a live Gemini key:
  the provider returned HTTP 429 with a multi-hour retry window. Every
  verification suite therefore exercises the real document, the real pipeline
  and the real exports, with the LLM and review text generated by a local mock
  that speaks the same wire formats. Wrapper equivalence and packaging are
  proven; summary *quality* against live providers is not yet.
- The facade has no user authentication beyond its token. Bind it to loopback
  and put a real authorization layer in front of it before exposing it.

## [1.0.0] - 2026-10-06

First working version. In-process Python wrapper around a separate
flat-tree application reached via `BOOKROOM_APP_ROOT`; TypeScript HTTP client
for the facade. Superseded by 2.0.0, which does not require the external
application.
